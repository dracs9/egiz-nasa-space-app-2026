# Математическая спецификация

Владельцы: MEMBER_E (научные решения, допуски) и MEMBER_D (реализация движка); рельеф и освещение — MEMBER_C. Статус: проект. Параметры §12 замораживаются коммитом пререгистрации на KICK-01. Код по этой спецификации пишем с 14.11 09:00.

## 1. Обозначения и соглашения

| Символ | Смысл |
| --- | --- |
| T | цель: район на Луне или место на Марсе; тело `b(T) ∈ {moon, mars}` |
| e | кандидат на Земле: квадрат 20×20 км (ID `GL_…`, `PR_…`, позже `KZ_…`) |
| o ∈ O | задача испытания из шаблона миссии (§7) |
| i | атрибут задачи |
| f_i(e,T) ∈ [0,1] | соответствие атрибута |
| F_o(e,T) ∈ [0,1] | соответствие задачи |
| C(S) ∈ [0,1] | покрытие кампанией S задач шаблона |
| p | шаг сетки, м; L = 2p — база уклона (центральная разность) |

**Единицы:** градусы для углов, метры для высот и расстояний, °C для температур, мм/год для осадков, доли 0–1 для долей. Единица — в имени поля (`_deg`, `_m`, `_c`, `_mm`, `_frac`, `_h`).

**Координаты:** широта и долгота в градусах. Для Луны и Марса — планетоцентрические, долгота восточная от −180 до 180. Расчёты рельефа ведём в локальной проекции с квадратным пикселем:

- Земля — UTM-зона центра квадрата (WGS84);
- Луна и Марс — азимутальная равнопромежуточная проекция с центром в цели и радиусом тела: `R_moon = 1 737 400 м`, `R_mars = 3 396 190 м`;
- у DEM PGDA своя полярная стереографическая проекция (MOON_ME, DE421); перепроецируем её в локальную.

Наклон оси к орбите (для освещения): Земля 23,44°, Марс 25,19°, Луна 1,54°.

## 2. Входные данные

Подробно — [DATASET_SPECIFICATION](DATASET_SPECIFICATION.md). Луна — DEM PGDA 5 м по районам; Марс — MOLA/HRSC 200 м; Земля — Copernicus GLO-30, MODIS LST, GPM IMERG, ESA WorldCover, MODIS MCD12Q1, позже MODIS MOD10A1 (снег).

## 3. Атрибуты рельефа

### 3.1 Сетка и огрубление

Окно 20×20 км вокруг центра. Огрубление до шага p — среднее по блокам: целое отношение шагов или `Resampling.average` при перепроекции. Пиксель валиден, если валидны все пиксели исходного блока. Если валидных пикселей меньше 50 % окна, атрибуты окна = `null`.

### 3.2 Уклон на базе

Базовая разность — центральная, на сетке шага p со смещением o пикселей (база `L = 2·o·p`):

```text
gx(i,j) = (z[i, j+o] − z[i, j−o]) / (2·o·p)
gy(i,j) = (z[i+o, j] − z[i−o, j]) / (2·o·p)
s_L(i,j) = atan( sqrt(gx² + gy²) ) · 180/π          [градусы]
```

Рамка шириной o пикселей исключается. Базы привязаны к критериям NASA:

| Тело цели | Тонкая база L_f | Сетка p, смещение | Региональная база L_r | Смещение на сетке p | Почему |
| --- | --- | --- | --- | --- | --- |
| Луна | 100 м | 50 м, o = 1 | 2 000 м | o = 20 | Посадка: уклон < 10° на 100 м; EVA: < 20° на 2 км (NASA, NTRS 20250009323) |
| Марс | 400 м | 200 м, o = 1 | 2 000 м | o = 5 | Тоньше 400 м глобального DEM Марса нет (MOLA/HRSC 200 м) |
| Земля | считаем обе: 100 м (p = 50 м) и 400 м (p = 200 м) | | 2 000 м | | Сравниваем только на базе тела цели |

### 3.3 Список атрибутов рельефа

| Имя | Определение | Ед. |
| --- | --- | --- |
| `slope_f_p50_deg`, `slope_f_p90_deg` | 50-й и 90-й перцентили s_{L_f} | ° |
| `frac_lt10_f` | доля пикселей с s_{L_f} < 10° (критерий посадки) | 0–1 |
| `frac_lt20_f` | доля пикселей с s_{L_f} < 20° (предел LTV) | 0–1 |
| `slope_r_p50_deg`, `slope_r_p90_deg` | перцентили s_{L_r} | ° |
| `frac_lt20_r` | доля пикселей с s_{L_r} < 20° (критерий EVA) | 0–1 |
| `relief_m` | P95 − P5 высоты на сетке p | м |
| `tri_f_m` | медиана TRI = (1/8)·Σ_{8 соседей} \|z_k − z\| на сетке тонкой базы (Wilson et al., 2007) | м |
| `elev_min_m` | минимум высоты (только проверки здравого смысла) | м |

Для Земли суффикс `_f` хранится в двух вариантах: `_f100` (база 100 м) и `_f400` (база 400 м). Движок берёт вариант по телу цели.

**Окна расчёта.** Атрибуты тонкой базы (`slope_f_*`, `frac_lt10_f`, `frac_lt20_f`, `tri_f_m`) считаются по центральному квадрату **10×10 км**. Атрибуты региональной базы, перепад и минимум высоты — по всему окну **20×20 км**. Правило одинаковое для цели и кандидата. Причина: расчёт на сетке 50 м для ~3 000 кандидатов вчетверо дешевле, а сравнение остаётся согласованным.

### 3.4 Сложность

O(N) на окно, где N — число пикселей: 200×200 (центральные 10 км при p = 50 м) или 400×400 (20 км при p = 50 м, только для целей Луны), 100×100 при p = 200 м.

## 5. Атрибуты освещения

### 5.1 Солнце на Земле

Положение Солнца — алгоритм NOAA Solar Calculator (на основе Meeus, *Astronomical Algorithms*): юлианское столетие → средняя долгота и аномалия → уравнение центра → истинная и видимая долгота → наклон эклиптики → склонение δ и уравнение времени → часовой угол H → высота h с поправкой на рефракцию → азимут. Для Земли используем **видимую** высоту, с рефракцией: тени создаёт видимое Солнце. Проверка — сравнение с astropy (VAL-01, E1).

### 5.2 Солнце у цели

Для района у южного полюса Луны на широте φ_T:

```text
h_max(T) = (90° − |φ_T|) + ε_moon,   ε_moon = 1,54°
```

Солнце обходит горизонт по азимуту на 360° за синодический месяц (≈ 29,53 сут). Это согласуется с характеристикой NASA «Солнце поднимается ~2–7° над горизонтом». Рельеф горизонта для цели учитываем только в модуле теней (§5.4).

### 5.3 Окна низкого Солнца на Земле

Для кандидата e (широта φ_e) и месяца m, при шаге 10 минут по всем дням месяца в опорном году:

```text
H_low(e,m)  = среднее по дням [часы, когда 0° < h ≤ h_max(T)]           [ч/сут]
A_low(e,m)  = медиана по дням [размах азимутов Солнца в эти часы]          [°]
```

Если окно освещения (§7) включено в задачу:

```text
f_hours  = at_least(H_low, a = 6 ч, τ = 3 ч)        # по умолчанию; см. §12
f_sweep  = at_least(A_low, a = 270°, τ = 90°)
f_snow   = snow_free_frac[m]                         # P1; в P0 = 1 с пометкой «снег не учтён»
f_light(e,T) = max_m  ( f_hours · f_sweep )^{1/2} · f_snow
best_month(e,T) = argmax_m
```

Сколько часов в сутки Солнце стоит не выше 7° (оценка по формуле равноденствия; проверить расчётом в LIGHT-02): широта 45° — около 1,3 ч (только у восхода и заката); 70° — около 2,8 ч; 77,5° — около 4,6 ч; 85° — весь световой день, но там лёд. Азимут на 360° при низком Солнце обходит только там, где Солнце не заходит и стоит низко, то есть практически на ледяном куполе. **Ожидаемый честный вывод** (гипотеза H-L2, проверяется): на свободной ото льда суше полный лунный режим недостижим, лучшее — несколько часов низкого Солнца в сутки вблизи равноденствий на высоких широтах. Это пойдёт в реестр разрывов.

### 5.4 Доля тени по DEM (P1)

Для сетки 30 м (Земля — Copernicus; Луна — PGDA 5 м → 30 м): окно анализа 10×10 км в центре окна 20×20 км, внешняя часть даёт преграды. Солнце с высотой h и азимутом az:

```text
повернуть DEM так, чтобы Солнце светило вдоль оси x (со стороны меньших x)
w_k = z_k + x_k · tan(h)                         # вдоль строки
shadow_i = max_{j < i} w_j > w_i  OR  нормаль отвёрнута от Солнца
sf(h, az) = доля пикселей окна анализа в тени
```

Сетка: h ∈ {1°, 2°, 3°, 5°, 7°}, az ∈ {0°, 45°, …, 315°}. Атрибут:

```text
Δsf(e,T) = среднее по сетке |sf_e(h,az) − sf_T(h,az)|
f_shadow = exp( −½ · (Δsf / 0,10)² )
```

Для кандидатов без DEM-окна `f_shadow` не вычисляется (`null`). Тогда задача «низкое Солнце» считается по §5.3 с пометкой «тени не учтены».

## 6. Функции соответствия атрибута

| Тип | Формула | Когда использовать |
| --- | --- | --- |
| `match(x, t, σ)` | exp(−½·((x − t)/σ)²) | Нужно совпадение со значением цели |
| `logmatch(x, t, σ)` | match(log10 x, log10 t, σ) | Масштабные величины: перепад, TRI |
| `at_most(x, a, τ)` | 1, если x ≤ a; иначе exp(−½·((x − a)/τ)²) | «Не больше»: осадки |
| `at_least(x, a, τ)` | 1, если x ≥ a; иначе exp(−½·((a − x)/τ)²) | «Не меньше»: голая поверхность, часы низкого Солнца |
| `colder(x, t, τ)` | 1, если x ≤ t; иначе exp(−½·((x − t)/τ)²) | Холод: чем ближе к цели снизу, тем лучше |
| `category(c_e, c_T, M)` | M[c_e][c_T] ∈ [0,1], матрица задаётся экспертом (P1) | Геология |
| `impossible` | 0 | Гравитация, вакуум, радиация — только в реестре разрывов (§9), в покрытие не входят |

Значения `null` у кандидата или цели → атрибут считается пропущенным (§7.2).

## 7. Соответствие задачи

### 7.1 Формула

```text
F_o(e,T) = exp( Σ_i w_i · ln(max(f_i, 10⁻⁶)) / Σ_i w_i )     # взвешенное геометрическое среднее
```

Почему геометрическое среднее: задача требует **всех** атрибутов одновременно — это мягкое логическое «И». Любой атрибут около 0 тянет задачу к 0. Альтернатива «жёсткое И» `min_i f_i` считается в анализе устойчивости (VAL-04).

### 7.2 Пропуски и допуск к задаче

- Если пропущено больше 30 % суммарного веса атрибутов задачи → кандидат **не допущен** к задаче: `F_o = null`, причина «missing».
- Иначе F_o считается по доступным атрибутам и помечается `partial`.
- **Ограничения пригодности** (не сходство): `water_frac ≤ 0,5`, `built_frac ≤ 0,2`. Для задач с освещением — `max_m snow_free_frac[m] ≥ 0,5` (P1). Нарушение → `F_o = null`, причина «constraint».

## 8. Кампания

### 8.1 Покрытие

```text
C(S) = Σ_o W_o · max_{e∈S} F_o(e,T) / Σ_o W_o,       S — набор кандидатов, |S| ≤ k
```

`null` считается как 0. Роль площадки в кампании — задачи, для которых она даёт максимум.

**Свойство.** C монотонна и субмодулярна: это функция «размещения объектов» (facility location) с неотрицательными весами. Поэтому жадный алгоритм гарантирует не меньше (1 − 1/e) ≈ 63 % оптимума. Мы сравниваем жадное решение с точным (VAL-02).

### 8.2 Точное решение на коротком списке

```text
U = ∪_o top_20(F_o)  ∪  top_20(F_single), где F_single(e) = C({e})
S*_k = argmax_{S ⊆ U, |S| = k} C(S),   k = 1, 2, 3        # полный перебор
S^g_k = жадный поиск на всём пуле
если C(S^g_k) > C(S*_k): U ← U ∪ S^g_k, повторить перебор
```

|U| ≤ 120 → C(120, 3) = 280 840 наборов × |O| ≤ 5 → векторизованно доли секунды. **Формулировка в подаче:** «точное решение на коротком списке, сверенное с жадным поиском по всему пулу». Не «глобальный оптимум».

Совпадения оценок разрешаем по порядку: больше покрытие → меньше площадок → лексикографически меньший набор ID.

### 8.3 Фронт

Для k = 1, 2, 3 показываем C(S*_k) и прирост. Если прирост от третьей площадки меньше 0,02, интерфейс рекомендует k = 2.

## 9. Реестр разрывов

- **Потолок атрибута:** `ceil_i(o,T) = max_e f_i(e,T)` по всему пулу. Если ceil_i < 0,1 → атрибут i — **разрыв** задачи o.
- **Потолок задачи:** `ceil_o = max_e F_o(e,T)`.
- **Физические разрывы** (всегда, вне покрытия): гравитация (Луна 0,165 g, Марс 0,38 g), вакуум или тонкая атмосфера, радиация, температура постоянно затенённых областей ниже −230 °C, реголит со своими свойствами. Для каждого — альтернативное средство из курируемой таблицы `gap_alternatives.csv` (SCI-02): термовакуумная камера, параболический полёт, имитатор грунта, прожекторы («Sun cart» JETT).

## 11. Сходство и пригодность

Атрибуты и F_o измеряют **сходство условий, важных для задачи**. Пригодность площадки зависит ещё от сезона, снега, доступа, разрешений и безопасности. Мы моделируем только то, что измеримо: ограничения §7.2, сезон и снег §5.3. Логистика (население, ночные огни) показывается справочно и в оценку не входит. Высокое F_o не доказывает физической эквивалентности и не заменяет полевую проверку.
