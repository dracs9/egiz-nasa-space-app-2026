## Kernel reproducibility and attribution

NASA/JPL NAIF and the ephemeris/kernel production teams are acknowledged. Sources and actual downloaded SHA-256 values are recorded in `data/kernels/manifest.json`. DE440s (about 31 MiB), `naif0012.tls`, `pck00011.tpc`, `moon_080317.tf` and `moon_pa_de421_1900-2050.bpc` are unmodified official generic kernels. The [official lunar FK](https://naif.jpl.nasa.gov/pub/naif/generic_kernels/fk/satellites/moon_080317.tf) specifies the PA-to-ME realization used to match the source lunar DEM. Earth/Mars runs load three required kernels; Moon loads all five. Binary/source kernels stay outside Git; their genuine computed numeric catalog is tracked. `make science-fetch` downloads only those official URLs and refuses changed fingerprints. EGIZ does not mirror an unmodified standalone SPICE Toolkit. It uses the installed third-party wrapper for its own scientific tool, subject to NAIF rules.

`SpiceyPy` is Andrew Annex's Python interface. CSPICE/NAIF/SPICE and kernel data are third-party technology. Open MCT is NASA software under Apache-2.0; its distribution includes other licenses retained in `openmct.js.LICENSE.txt` and `copyright-notice.*`. EGIZ's adapters, quasi-static rover equations implementation, measured-mission coverage utility, campaign protocol, original vehicle geometry and experiment UI are project contributions. No ownership of NASA's engines/data or institutional endorsement is asserted.

The host's first sandboxed package-install attempt could not resolve PyPI because network access was restricted. Installation with the allowed network execution succeeded; this was an environment boundary, not a package compatibility failure. The loopback dev server similarly required local socket permission. Neither needed a remote deployment or user account.

## Known implementation limits

The service uses a single-threaded loopback HTTP server because CSPICE's global kernel pool is managed per request. It accepts only known measured site IDs, bounded JSON bodies and timezone-qualified epochs from 2000–2040. No user-specified file path, kernel URL or arbitrary code is accepted over HTTP. Vite proxies `/api/science`; a static build has recorded geometry but no live native service.

Geometry uses geometric `NONE` positions. Earth is WGS84 geodetic at zero height with text-PCK IAU_EARTH orientation, not precision EOP/ITRF. Moon uses binary DE421 lunar orientation in MOON_ME_DE421 through the matching FK. Mars uses text-PCK IAU_MARS orientation and the DE440s system barycenter approximation. Terrain occultation is not implemented. Solar flux uses an explicit 1361 W/m² reference at 1 AU. Surface transmission, panel efficiency and mission physics are assumptions. Open MCT plots simulator output and does not validate its physical fidelity.

The full Apache-2.0 license is packaged in `web/public/licenses/apache-2.0.txt`. Open MCT's normal stock plot runs in development/ordinary static mode. In the strict offline CSP, its runtime Vue-template compiler is blocked, so EGIZ registers a CSP-safe recorded SVG view through Open MCT's official view and telemetry APIs. This view is visibly identified as EGIZ's contribution, not NASA's stock plot. No `unsafe-eval` permission was added. Other optional upstream tools that require runtime templates remain outside strict-CSP support.
