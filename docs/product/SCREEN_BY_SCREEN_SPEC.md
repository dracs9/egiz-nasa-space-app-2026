# Спецификация экранов

Владельцы: MEMBER_A (каркас, карта, Brief, Twin, Dossier), MEMBER_D (кампания, задачи, разрывы, панель площадки, матрица, Evidence), MEMBER_F (тексты `copy.json`). Компоненты и файлы — [FILE_BY_FILE_BUILD_PLAN](../engineering/FILE_BY_FILE_BUILD_PLAN.md). Все строки интерфейса берутся из `web/src/content/copy.json` по ключам вида `brief.title`.

## S0. Рамка приложения (все экраны) — P0, MEMBER_A

| Элемент | Что делает |
| --- | --- |
| Шапка: логотип-текст «Egiz», вкладки Brief · Campaign · Evidence (P1: Twin · Matrix) | Переход по маршрутам `#/…`; активная вкладка подчёркнута. Маршрут по умолчанию `#/` открывает Campaign с Mons Mouton, шаблоном по умолчанию и k = 3 — человек со ссылкой сразу видит ответ; Brief — для смены вопроса (RED_TEAM_REVIEW P1) |
| Плашка synthetic | Видна, если любой загруженный файл имеет `synthetic: true`. Текст: «SYNTHETIC DEMO DATA — not NASA observations». Не закрывается |
| Индикатор «Offline» | Видна, если не загрузилась подложка карты; данные работают |
| Подвал | «Data: NASA (LOLA/PGDA, MOLA, MODIS, GPM IMERG, NASADEM, GIBS) · ESA (Copernicus DEM, WorldCover)», ссылка на Evidence → Sources, оговорка о независимости от NASA |

**Состояния.** Загрузка: скелет панелей и строка «Loading mission data…». Ошибка данных: экран «Data failed to load» с причиной (сеть, схема, версия) и кнопкой «Retry». Версия контракта не совпала: «Data version x.y not supported by this app (expects 1.x)».

**Адаптивность.** ≥ 1280: три колонки. 768–1279: две колонки, правая панель — выдвижная. < 768: одна колонка, панели — вкладки внизу.

## S1. Mission Brief — P0, MEMBER_A (тексты — MEMBER_F)

**Цель:** за 15 секунд задать вопрос.

| Секция | Содержимое | Элементы и что они делают |
| --- | --- | --- |
| Заголовок | «Design an Earth test campaign for a Moon base site or a Mars landing site» | — |
| 1. Target | Карточки целей: тело (цвет Луны или Марса), название, широта, источник DEM, миниатюра рельефа | Клик выбирает цель (радио-группа, стрелки ← →). P0: Mons Mouton и Jezero |
| 2. Mission | Шаблон по телу: Moon base ops или Mars surface ops; список задач с флажками и короткими описаниями | Флажок включает или выключает задачу (W_o = 1 или 0). В P0 веса фиксированы; в P1 — ползунок 0–3 у каждой |
| 3. Campaign size | Переключатель k = 1, 2, 3 (по умолчанию 3) | Задаёт k |
| Кнопка | «Design campaign» | Переход на `#/campaign?target=…&k=…&obj=…`. Неактивна, если нет ни одной задачи; подсказка «Select at least one objective» |
| Подпись | «Fidelity measures similarity of test-relevant conditions, not suitability. See Evidence.» | Ссылка на Evidence |

**P0-поведение:** кампании для шаблона по умолчанию предрасчитаны (`campaigns`). Если пользователь выключил задачу в P0 — показываем предрасчитанный вариант, если он есть, иначе подсказку «Live re-optimization available in full version» (P1 убирает ограничение).

**Анимация:** выбор карточки — подсветка рамки 150 мс.

## S2. Campaign Planner (главный) — P0, MEMBER_C (панели: Objectives, Frontier, Campaign card, Earth cannot test; WEB-04) и MEMBER_A (карта, раскладка; WEB-03)

**Цель:** ответ на вопрос и его объяснение.

| Колонка | Секция | Содержимое | Элементы и что они делают |
| --- | --- | --- | --- |
| Левая | Objectives | Для каждой задачи: название, полоса покрытия кампанией (0–1), отметка «Earth ceiling» на той же полосе, номер площадки, которая её закрывает | Клик по задаче → фокус `obj=…`: карта показывает кандидатов этой задачи. Повторный клик снимает фокус |
| Центр | Map | Подложка NASA GIBS; точки кандидатов (цвет — F_o выбранной задачи по шкале cividis, серые — не допущены); маркеры 1–3 площадок кампании; для Луны — подпись лучшего месяца освещения | Клик по точке → панель площадки (`site=…`); колесо — масштаб; кнопка «Fit campaign» — показать все площадки |
| Центр, сверху | Frontier | k = 1, 2, 3 с покрытием; выбранный k выделен | Клик меняет k |
| Правая | Campaign card | «Coverage 0.xx with k sites»; для каждой площадки — номер, название (у мест практики — собственное имя; у остальных — страна по LSIB и координаты), роль (задачи), лучший месяц (для Low-Sun), флаги `partial` | Клик по площадке → панель площадки |
| Правая | What Earth cannot test — plan these in a lab | Атрибутные разрывы (потолок < 0,1) и физические разрывы с альтернативами (камеры, имитаторы, полёты) | Наведение — пояснение и источник |
| Правая | Method note | «Exact within a shortlist of N candidates, verified by greedy search over all M candidates» | Ссылка на Evidence |

**Пустое состояние.** Нет допущенных кандидатов для задачи: в полосе «No eligible Earth site» и причина (missing или constraint).

**Ошибка Worker (P1).** Если пересчёт не уложился в 2 с: «Re-optimization timed out; showing precomputed result».

**Анимация.** Смена k — маркеры появляются с задержкой 80 мс по порядку. Фокус задачи — перекраска точек 200 мс.

**Доступность.** Карта дублируется таблицей «Top candidates for this objective» (переключатель Map / Table).

**Приоритет ответа.** Карточка кампании видна без прокрутки на ширине 1280 px; на телефоне она идёт первой, карта — ниже (RED_TEAM_REVIEW P3).

## S3. Панель площадки — P0, MEMBER_D (WEB-05)

Выдвижная панель справа (на мобильном — нижний лист).

| Секция | Содержимое |
| --- | --- |
| Заголовок | ID, координаты, регион, тип пула (global sample, practice site, Kazakhstan) |
| Роль в кампании | Задачи, которые площадка закрывает, и F_o по каждой |
| Атрибуты | Для каждой задачи — строки атрибутов: имя, значение кандидата и цели с единицами, функция и допуск, f (полоса), источник набора. Пропуски — «missing» серым |
| Освещение (для целей Луны) | 12 столбиков H_low по месяцам, линия A_low, лучший месяц; (P1) доля дней без снега |
| Справочно | Плотность населения, «Suitability not assessed» |
| Ссылки | «Open Same-Sun view» (P1), «Copy link» |

**Состояния.** Площадка не найдена: «Site not in current dataset».

## S4. Матрица соответствия — P1, MEMBER_D

Строки — площадки кампании и топ-10 альтернатив. Столбцы — атрибуты, сгруппированные по задачам. Ячейка — f с цветом cividis и числом. Клик по ячейке — всплывающее окно с доказательством (значения, функция, источник). Сортировка по столбцу. Переключатель «Show partial / missing».

## S5. То же Солнце — P1, MEMBER_A

**Цель:** увидеть, что площадка в выбранное окно повторяет освещение цели.

| Элемент | Что делает |
| --- | --- |
| Две панели: цель (слева) и площадка (справа) | Отмывка рельефа 30 м при одинаковой высоте и азимуте Солнца; тени — тёмным; масштабная линейка 2 км |
| Ползунок высоты Солнца (1°, 2°, 3°, 5°, 7°) | Переключает пары заранее отрисованных картинок |
| Кнопка «Sweep azimuth» | Анимация азимутов 0–315° с шагом 45° (по 600 мс), пауза по клику |
| График sf(h) | Доля тени цели и площадки по высотам, среднее по азимутам |
| Подпись окна | «At this site, Sun ≤ h_max for H h/day in [months]» |
| Оговорка | «Earth's sky scatters light; shadows are not as black as on the Moon» |

**Нет картинок для площадки:** «Same-Sun images are available for shortlisted sites» и список доступных.

## S7. Режим «Казахстан» — P1, MEMBER_A

Переключатель в S2 «Global / Kazakhstan only». В режиме «Kazakhstan only» кампания считается только по квадратам `KZ_`. Рядом — сравнение «Kazakhstan covers X of global Y» и отдельные разрывы. Нет кандидатов Казахстана — «No Kazakhstan tiles in dataset (P1 data not loaded)».

## Глобальные правила интерфейса

**Простые слова на экране, термины — в подсказках** (RED_TEAM_REVIEW P2): «How well Earth can rehearse each test» вместо «objective fidelity», «Campaign coverage» с подсказкой, «Earth ceiling» с подсказкой «the best any Earth site reaches», «What Earth cannot test» вместо «gap ledger». В P0 подписи пишет MEMBER_A по этому правилу, в P1 — MEMBER_F в `copy.json`.


- Каждый элемент управления меняет данные или вид; декоративных кнопок нет.
- Каждое число кликабельно до источника (S3, S4, S6).
- Цвет тела: Луна — песочный, Марс — терракотовый, Земля — бирюзовый (DESIGN_SYSTEM).
- Цифры моноширинным шрифтом, единицы всегда видны.
- Нет логотипов NASA и других агентств.
