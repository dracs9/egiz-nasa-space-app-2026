# 05 · Архитектура

Код не будет узким местом: ИИ напишет его быстро. Узкие места — правильность данных и сборка в последний час. Поэтому работаем в одном репозитории, заранее согласуем формат данных, а за техническую координацию отвечает один человек — тех-лид.

## Модули

| Модуль | Кто | Что делает | Выход |
| --- | --- | --- | --- |
| A · Земля | Кодер A | Скрипты Google Earth Engine, сетка 20×20 км по Казахстану и эталонам мира | `features_earth.json` |
| B · Луна и Марс | Кодер B | Окна из Cloud Optimized GeoTIFF и STAC, те же метрики | `targets.json` |
| C · Движок | Кодер C | Нормировка, скоринг, объяснения, автотесты | `results.json` |
| D · Сайт | Кодер D, тех-лид | Карта, Twin view, досье, деплой | Сайт на Vercel или GitHub Pages |

```text
A · Земля (Earth Engine) ──► features_earth.json ─┐
                                                   ├──► C · Движок ──► results.json ──► D · Сайт
B · Луна и Марс (COG, STAC) ──► targets.json ─────┘
```

## Правила для кодеров

1. Одна функция `terrain_metrics(dem, pixel_m)` для всех трёх тел. Никаких своих формул у каждого.
2. Одно разрешение и один размер квадрата, например 200 м и 20×20 км. На детальном рельефе уклоны всегда выходят круче.
3. В первый час хакатона пишем схему JSON и фейковые данные по ней. Сайт и движок работают на фейке, пока считаются настоящие данные.
4. Сайт статический: всё посчитано заранее, веса пересчитываются в браузере. Сервер не нужен, демо не упадёт.
5. Глобальные файлы не качаем, читаем только нужные окна. 11-гигабайтный DEM Марса по Wi-Fi школы не скачается.
6. Один интегратор сливает ветки. Каждый записывает использование ИИ в [журнал ИИ](ai-log.md).

## Контракт данных

Одна запись на квадрат Земли или на цель на Луне или Марсе. Поля одинаковые для всех тел.

```jsonc
{
  "id": "MARS_JEZERO",
  "body": "mars",              // earth | moon | mars
  "lon": 77.45, "lat": 18.44,  // место посадки Perseverance
  "tile_km": 20, "res_m": 200,
  "slope_p50_deg": null,       // всё ниже считает terrain_metrics()
  "slope_p90_deg": null,
  "frac_slope_lt15": null,
  "relief_m": null, "roughness_m": null,
  "t_min_c": null, "t_max_c": null,
  "lithology": [],             // теги от геолога со ссылкой на источник
  "sources": ["MOLA-HRSC DEM", "THEMIS"]
}
```

## Стек

- **Данные и движок:** Python — `earthengine-api`, `rasterio`, `numpy`, `pandas`.
- **Сайт:** Vite, MapLibre GL с подложками Trek, three.js для 3D-двойников, ECharts для графиков.
- **Деплой:** Vercel или GitHub Pages.
- **Связь:** Discord с каналами по модулям.
